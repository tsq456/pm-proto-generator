## 已认可的方向

- 正式文档采用“页面规格说明”，悬浮入口可保留“原型说明”。
- 章节名称采用专业名词：“页面概述”“功能范围”“角色与权限”“页面结构”“字段说明”“业务规则”“交互说明”“验收要点”“待确认事项”。
- 筛选字段、展示字段、表单字段归入字段说明；状态流转归入业务规则。不适用章节省略，顺序按页型调整。
- 权限集中说明，具体交互引用；功能范围概括能力，操作条件、成功、失败及跨页影响放入交互说明。
- 表头调整：“在本页做什么”改为“操作权限”，“看不到/不能做”拆为“可见范围”和“操作限制”，“副作用”改为“关联影响”。
- 去掉正文外层容器边框、圆角和外围浅蓝底色，使用连续白底；目录与正文只保留淡分隔线和适量留白。
- 缩小章节标题，明确标题层级；目录默认两级，细操作按需展开。
- 字段、权限和规则对照保留表格，边线淡化；复杂交互按操作分节，避免超宽表格。
- 页头集中展示版本、评审状态和更新时间；原型覆盖与产品规则分开，阻塞事项突出显示。
- 删除无效填表内容：产品要求应写业务行为而非“正式对接 API”；界面位置应写具体区域而非“本页主区域”；“页内可见”不能作为通用说明。
- ProtoMock 等技术实现细节归入末尾“原型演示说明”，不与业务章节并列；演示覆盖用“已演示 / 部分演示 / 未演示”。
