# 逐页实现选型流程

主技能接收就绪 Spec 后、编写或结构性修改业务 HTML 前执行。只生成 Spec 不执行；纯文案、样式或局部修复只核对受影响区域，沿用已有选择，不重做整页选型。此流程是技术适配，不重新设计业务或增加产品审批。

## 1. 提取本页要求

读取接收记录、本页 Spec 及必要共享规则，提取页面职责、区域、字段、操作、状态、固定对象、入口返回和明确不做的内容。只处理就绪范围；无法唯一确定的业务含义反馈上游，不用组件默认行为补成业务规则。

## 2. 确定页面类型与承载方式

判断主职责：列表查询、只读详情、工作台、表单、概览或结果页。页面类型描述业务职责，layout 描述空间组织，两者不是一一对应。

确认独立页、Tab、弹窗、抽屉及其宿主；沿用上游已明确的承载方式。上游未指定的表单载体按 [表单载体](form-carrier.md)适配。工作台可包含树、摘要、列表，不因出现表格就改成列表页；浮层和 Tab 不新增 page-id。

## 3. 选择壳层和 layout

先沿用目标包的壳层及同类页面，再从 [布局索引](layouts/README.md)选骨架。选择能承载本页要求的单一或组合布局，列明区域、顺序和与默认骨架的差异。没有完整匹配的 layout 时组合已有区域；确需新布局时说明原因，复用现有容器、间距和 Token，不硬套近似模板。导航仍按已确认 sitemap，不由布局选择反推菜单。

## 4. 拆出区域与组件

逐区域列出组件及所需行为。例如：树的搜索与选中、表格的独立编码列与禁止批量、详情 Tab 的切换、抽屉的只读关闭。按 [组件索引](components/README.md)、业务组合和 [控件索引](controls/README.md)定位规范。不能只写“用 Table”，要能判断已有实现是否满足本页要求。

## 5. 检查实际可复用资源

先查目标包已有同类页面、共享 CSS/JS，再查仓库 kit、组件规范和必要示例。记录可定位的文件与 class/函数；规范有描述不等于已有可运行组件。检查实际行为、状态支持、依赖与全局初始化副作用，避免只复用外观。

重点检查：表格脚本是否自动添加复选框、筛选是否自动变成多选、浮层是否重复绑定事件、数据是否跨页一致。复用代码时保留本页业务例外，不把其他页面的字段、权限、操作或种子照搬过来。

## 6. 按缺口选择实现方式

| 判断 | 处理 |
| --- | --- |
| 已有实现满足本页行为 | 直接复用，引用实际位置 |
| 已有基础能力可通过组合或局部适配满足 | 优先组合/配置，必要时增加最小 CSS/JS，不复制另一套组件 |
| 确认无可用实现，当前页确有要求 | 新增最小实现，记录缺口、原因、落点与验收点；遵循静态技术栈和现有 Token |
| 单页专用扩展 | 留在当前页或包内专用资源；有具体多页复用需求时再提取包内共享组件 |
| 需要升级仓库共享 kit | 作为明确共享资源变更评估影响与回归范围，不因单包交付自动覆盖其他包 |
| 技术栈或复杂能力无法满足要求 | 报告不支持的行为及受影响范围；继续独立可实现部分，不擅自改为占位或宣称完成 |

已明确占位的内容只实现占位。新增实现不等于新增业务能力；不引入未要求的批量、提交、角色或状态。不得为了补齐官方目录扩建组件库。

## 7. 实现、联调与验收

按选型记录实现，接入固定场景数据和 Runtime，导航变化时同步相关入口。逐项对照本页要求与组件行为，核对独立编码、无批量、占位等例外；新增或适配共享组件时回归本批使用它的页面。验证实际交互、跨页对象与返回关系，再按 [实现检查](implementation-checklist.md)完成本批验收。

若实现过程中发现选型不适合，可以调整技术方案并更新记录；不得静默改变上游要求。业务冲突回到接收记录，技术取舍留在实现记录。

## 简短实现记录

在包内一份 `docs/implementation-map.md` 中按 page-id 记录，只维护本批新增或受影响部分，不生成多份规划文档，也不把技术选型塞入上游 Spec。旧包不要求补齐全部历史页面。

每页填写：

- **依据**：接收批次、Spec 路径与版本。
- **页面类型 / 宿主**：如工作台；编辑抽屉归本页。
- **壳层 / layout**：现有壳层与选用或组合的骨架。

| 区域与所需行为 | 组件 | 实际复用位置 | 处理方式与原因 | 实现落点 | 验收点 |
| --- | --- | --- | --- | --- | --- |
| 按本页填写 | 具体组件 | 包内或仓库路径及 class/函数；无则注明检索范围 | 复用 / 组合 / 适配 / 新增 / 受阻 | 页面或共享资源路径 | 可观察的结果 |

仅需要记录有助于实施与回归的信息；小修复可在已有页条目追加差异。无需用户批准这份技术记录。验收后记录结果和限制，产品要求与实际覆盖仍按既有逐页说明协议维护。
