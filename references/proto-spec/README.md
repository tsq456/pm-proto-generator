# 逐页 Spec 协议

逐页说明是上游文档的实现视图：**保留原稿 → 派生逐页说明 → 按说明实现并回填覆盖**。业务决策始终追溯上游，不因现有 HTML 不同而修改需求。

## 生成入口

使用 [proto-spec-generator](../../skills/proto-spec-generator/SKILL.md) 接收文档包，按 [接收放行规则](review-gate.md)判断就绪，再用 [页面模板](spec-template.md)转换。只生成说明不要求 HTML 已存在或挂载 Runtime。

新页使用 `proto-spec/<page-id>.md`，文件名 = frontmatter id = sitemap id = Runtime pageId。正文围绕本页区块、字段、权限、交互和验收；浮层写入宿主页，不另建业务页面。

## 来源与事实

每页正文包含来源文档、版本/批次、章节与接收记录的相对链接。多份源文档合成一页时逐项注明规则来源；公共定义引用唯一原稿，相关本地说明保留实现所需的准确内容，不发明另一份定义。

分开记录：

| 项目 | 含义 |
| --- | --- |
| 产品要求 | 上游已确认的业务行为 |
| 原型覆盖 | 已演示 / 部分演示 / 未演示；生成说明时尚无实现则写未演示 |
| 待决事项 | 真正缺失或冲突的业务决策，不包括缺技术字段名 |

已确认原稿与原型不一致：修实现或记录覆盖缺口，不改原稿。历史无来源材料可整理现状并标“来源待补”；仅从页面可见内容不能推定不可见的权限与业务规则。

## 内容最低要求

- 页面职责、入口、返回与上下文；字段按筛选/表单/展示区分。
- 关键操作包含条件、校验、成功/失败、数据变化及跨页影响；查询和关闭可简写。
- 涉及状态变化时给出相关状态规则；保留上游图示及必要解释，不因本地阅读器未渲染 Mermaid 而丢弃语义。
- 固定业务数据、前置条件和验收可对应；本地技术映射集中记录，不要求上游创造代码命名。
- 占位、不做和必须演示分别写明；明确占位不能扩大成真实提交。
- 已确认的字段顺序、页面载体、操作入口和文案优先；kit 规范仅填补未指定的通用表现。

## 挂载与更新

实现业务 HTML 时才按 [标准片段](../mount-snippet.md)挂载。主技能负责 PRD 汇总和包内更新记录，见 [changelog-guide.md](changelog-guide.md)。

## 旧包兼容

Runtime 继续支持 `<page-id>/spec.md` 和 `meta.yaml` 配历史分册；保留旧包读取能力，不代表继续维护两套生成规范。旧分册模板已移除，新建内容统一使用 [逐页模板](spec-template.md)，交互、字段、业务流程和状态流转均写入该文件。历史包保持原位，不批量迁移或删除确认记录。
