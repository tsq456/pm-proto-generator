# 页面规格说明模板（默认 · 扁平单文件）

默认每页只维护：

```text
proto-spec/<page-id>.md
```

文件名 = **page-id**（如 `tenant-list.md`），**不要**用中文文件名。YAML frontmatter = 页 meta；正文 = Screen Spec。

旧路径 `proto-spec/<page-id>/spec.md` 仍可读；新页不要再建子目录。  
总规则（谁驱动谁、产品 vs 演示）：[README.md](./README.md)。

## Frontmatter 字段

| 键 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | = page-id = 文件名（无 `.md`） |
| `name` | 是 | 中文显示名 |
| `version` | 建议 | 如 `0.1.0` |
| `status` | 建议 | `draft` \| `reviewing` \| `confirmed` \| `deprecated` |
| `updatedAt` | 建议 | `YYYY-MM-DD` |

`version` 是本地转换版本，不冒充上游版本。`confirmed` 仅在接收记录具备适用于当前来源版本的授权依据、依赖无冲突且转换忠实时沿用；不另设派生文档审批。旧 `docs/spec-review.md` 仍可作为依据。状态本身不能放行，见 [就绪规则](./review-gate.md)。

## 文风

**Screen Spec**：写清本页行为与口径；禁止空泛 PRD 套话。

- 页面名称由阅读器页头显示；正文从二级标题开始，章节内用三级标题。具体操作可直接作为交互说明下的三级标题，额外细节使用四级标题。
- 功能范围只概括功能、具体界面入口、产品行为与演示覆盖；交互条件、成功/失败和关联影响集中写在交互说明。
- 权限只在“角色与权限”集中维护，具体操作引用相关权限；未明确的数据可见范围须列为待确认，不自行推断。
- 用“新增弹窗”“列表工具栏”等具体区域名；禁止用“本页主区域”“页内可见”“正式对接 API”等无效占位替代业务说明。
- 字段、权限、规则适合表格；复杂交互逐操作分节，避免八列宽表。可选“原型演示说明”置于末尾，集中记录 ProtoMock 等演示机制。
- 阻塞项在“待确认事项”开头用引用块强调：`> **阻塞确认**：…`。无未决事项则省略该节；不能把未实现当作未确认。  
**产品要求**与**原型覆盖**分列；勿把「原型未做」写成「待产品确认」。

## 字段表怎么用

- 按本页实际用途拆表，**不必**三张都出现。
- 「必填」必须带场景（创建时 / 编辑时 / 筛选无必填等），禁止一张大表混用导致歧义。
- 上游明确展示次序优先；未指定时详情「展示字段」按扫读分层排行，勿按表单填写序照抄；通栏（备注、附件）放表末。
- 字段类型直接写在本页表中；已有旧包可保留原格式，不再生成独立字段文件。
