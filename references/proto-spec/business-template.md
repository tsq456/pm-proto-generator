# business.md 模板（文风参考 · 旧包兼容）

> **新 Spec** 直接按 [spec-template.md](./spec-template.md) 写扁平单文件即可。本文保留文风与分区表参考；勿再要求单独 `business.md`。

写的是 **Screen Spec（本页说明书）**，不是通用 PRD 填空。读者打开旁路 Drawer 时，应能对照页面上的分区、筛选字段、按钮理解「这页干什么」。

列表型内容仍优先用 Markdown 表格（Drawer 好读）；**单元格要写具体行为/口径，禁止空泛口号**。

生成时先读 [README.md](./README.md) 总规则（含 Spec/原型驱动、产品 vs 演示）。

---

## 推荐结构

```md
# 页面概述

用 1～3 句说明：**本页在产品里解决什么、用户带着什么任务进来**。
禁止只写「提升效率 / 统一管理」一类可套任何页的句子。

可选接短节「页面关系」：上游入口 / 并列页 / 下游跳转（写 page-id 或中文名 + 链）。

# 功能范围

| 功能 | 界面入口 | 说明 |
| --- | --- | --- |
| … | 顶部筛选 / 列表 / 右侧抽屉… | 一句话说清该区域完成的事 |

# 角色与权限

| 角色 | 可见范围 | 操作权限 | 操作限制 |
| --- | --- | --- | --- |
| … | 可访问区域及数据范围 | 新建、启停、只读等具体操作 | 禁用或隐藏的操作 |

# 页面结构

| 页面分区 | 控件/内容 | 说明 |
| --- | --- | --- |
| 查询区 | 计划名称、状态… | 与页面卡片/标题对齐；写默认筛选如有 |
| 列表区 | 表格列摘要 | 数据从哪来、默认排序一句话 |
| … | … | … |

# 业务规则

| 规则 ID | 规则名 | 说明 |
| --- | --- | --- |
| BR-001 | 仅启用可生成任务 | 只有已启用计划才可以生成任务 |

规则名用业务语言（「列表数据来源」「启停条件」），不要只有编号。
```

## 列约定

| 章节 | 列 | 备注 |
| --- | --- | --- |
| 功能范围 | 功能、界面入口、说明 | 「对应界面」必须能指到本页可见区域 |
| 角色与权限 | 角色、可见范围、操作权限、操作限制 | **合并**原角色+目标；写本页权限差，不写岗位说明书 |
| 页面结构 | 页面分区、控件/内容、说明 | 与 HTML 分区一致；可含默认值/数据来源一句 |

| 项 | 说明 |
| --- | --- |
| 列表数据来源 | … |
| 默认排序 | … |
| 空态/无权限 | … |

## 文风（MUST）

1. **对照页面写**：出现的筛选字段名、按钮文案、列名，尽量与 HTML 一致。
2. **禁止空泛目标句**单独撑章节（如「降低人工成本」）；若写目标，必须落到本页可验证行为。
3. **禁止**用「查询区域｜筛选计划」这种复述布局、不讲行为的模块行。
4. 单元格内不写长段落；超长拆行或放到文末「补充说明」。
5. 规则 ID 页内唯一、稳定；更新时尽量不改号。
6. 样例见 `examples/proto-spec-demo/proto-spec/inspect-plan-list.md`（扁平单文件；本节供拆分或迁入正文时对照）。

## 生成约束（Skill / Generator）

1. 默认输出上表结构；禁止用 `## 管理员` / `## BR-xxx` 分段堆叠规则正文。
2. 先扫目标 HTML（或 sitemap + 字段）再写 Spec；**不得**只按模板空表生成后再与页面无关。
3. 包级愿景、里程碑放 `docs/prd-intro.md` / 包级 PRD，**不要**塞进每页 business 重复一遍。
