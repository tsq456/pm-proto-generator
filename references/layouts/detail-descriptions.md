# 详情页：描述列表

> 本文为上游未指定时的 kit 默认表现。已确认页面 Spec 的布局、列序、字段、交互与能力边界优先；不据此新增业务能力。

对齐官方：`ob-design` Descriptions 的**表格式**（左标签右值）。

**组件级细则**：[detail-page](../components/detail-page.md)。

## 适用

- 只读详情、资源概览、审核查看

## 区块结构

### 无 Tab

```
.ob-content
├─ .ob-page-title
│    └─ .ob-page-title__main（左侧返回图标 + h1，标题不含状态）
└─ .ob-stack → .ob-card → .ob-desc
```

### 有 Tab（MUST：一体大卡）

```
.ob-content
├─ .ob-page-title
│    └─ .ob-page-title__main（左侧返回图标 + h1）
└─ section.ob-card.ob-card--tabs[data-tabs]
   ├─ .ob-card__tabs
   │    └─ .ob-tabs（页签；可右侧 .ob-card__tabs-extra 放操作）
   └─ [data-panel].ob-card__body …（勿再套一层同名标题卡）
```

- Tab 文案已表达分区时，**禁止**在 panel 内再写同名 `.ob-card__title`
- 页签内表格/描述表的操作（如「新增图纸」、基本资料「编辑」）放 `.ob-panel-toolbar`，**固定在表格或 `.ob-desc` 左上方**；不要右对齐、不要用重复标题栏、不要放页头冒充「编辑整页」
- 基本资料「编辑」在**当前详情页**打开 Drawer，禁止 `list.html?edit=`
- 详情 Tab 内嵌表必须用普通 `.ob-card__body`（有内边距），**禁止** `.ob-card__body--flush`（flush 仅列表主表）
- 状态字段（启停、空置/出租中、抵押、框选等）在 `.ob-desc` 与内嵌表都用 `.ob-status` 圆点，规范见 [table-field-visual](../components/table-field-visual.md)

## 描述列表布局（MUST）

**左标签、右值**；标签列**淡底**，值列**白底**（参考运维/配置台账表）。**不做行斑马纹**。

```html
<dl class="ob-desc">
  <div class="ob-desc__item">
    <dt>处置人员</dt>
    <dd>李朝阳</dd>
  </div>
  <div class="ob-desc__item">
    <dt>验收人员</dt>
    <dd>王宸</dd>
  </div>
  <div class="ob-desc__item ob-desc__item--full">
    <dt>备注</dt>
    <dd>—</dd>
  </div>
</dl>
```

### 列数判断

只统计本卡内**非通栏**短字段。

| 修饰 | 列数 | 何时用 |
| --- | --- | --- |
| 默认 / `.ob-desc--2` | **2** | 短字段 ≤8；值偏长；抽屉/Modal |
| `.ob-desc--3` | **3** | 短字段 ≥9 且多数值短；宽桌面 |
| `.ob-desc__item--full` | 通栏 | 备注、长地址、说明 |

### 视觉

- 标签列：`--ob-color-bg-secondary`；值列：`--ob-color-bg-default`（白）
- 细分割线；勿粗边框、深表头、行斑马、强阴影
- 每项包在 `.ob-desc__item` 内
- 格线由 kit 用 **1px gap 露底**绘制，线在格子之间，不会被下一项盖住。禁止 nth-child 去边、禁止负边距叠边。
- 单独落在一行的短字段也用 `.ob-desc__item--full`（MUST），避免空格露出格线底色；见下方「硬约束」

## 字段摆放顺序（MUST 骨架）

描述表按**扫读**排，不按后端字段序、也不默认照搬表单填写序。表单可按填写负担排；详情 DOM 顺序按本节。视觉表达（普通 / 分类 / 状态）仍见 [table-field-visual](../components/table-field-visual.md)。

同一 `.ob-desc`（或同一分区卡内）默认自上而下：

| 层 | 放什么 | 例子 |
| --- | --- | --- |
| 1 身份 | 名称 → 编号/编码 | 园区名称、区域名称；页头 `h1` 已是名称时可省略名称格、只留编号 |
| 2 状态 | 启停、经营/生命周期等 | 启用/停用、空置/出租中；用 `.ob-status`，**不要**进 `h1` |
| 3 分类 | 类型、分类、业务特征 | 区域类型、媒介类型、证书类型 |
| 4 归属与位置 | 上级/所属、部门、负责人、位置 | 所属园区、管理部门、负责人、所在位置 |
| 5 业务度量 | 面积、金额、尺寸、时效等 | 证载面积、参考租金、完成时效 |
| 6 审计 | 创建人 → 创建时间（全包统一此序） | 创建人、创建时间 |
| 7 通栏收尾 | 备注 → 长说明 → 附件/图片 | 一律 `.ob-desc__item--full` |

缺某层就跳过，不要为凑层硬拆空格。层内字段仍可按业务微调，但**不要跨层乱插**（例如审计插在备注后面、类型插在附件后面）。

### 硬约束

1. **一行一字段必须通栏（MUST）**：两列布局下，凡本行只有一个字段（含落单短字段），一律 `.ob-desc__item--full`。禁止半行字段旁露出空白格（格线底色）。
2. **通栏只收尾**：备注、长地址、富文本、附件/图片放本分区末尾；其后**禁止**再排短字段（含创建人/时间）。
3. **成对并排**：管理部门/负责人、创建人/创建时间、起止日期、面积/金额等尽量同一行左右相邻，不要隔一行对不上。
4. **与表单可字段同集、顺序可不同**：Spec 写「字段同列表/表单」只约束**有哪些字段**；详情展示序按本节。列表列序也不必与详情一一对应（列表另有名称+编号叠放等规则）。
5. **多卡 / 多 Tab**：每张描述表各自走同一骨架。跨卡顺序优先：主身份卡 → 业务扩展卡 → 经营/价格等；流程类详情（如工单）按「诉求 → 处理 → 评价」分块，**块内**仍用本骨架。

### Spec

详情页「展示字段」表的**行序 = `.ob-desc` 展示序**；写 Spec 时就按上表分层排，实现时勿再猜。

## 约束

- 字段只读；**基本资料「编辑」**放该分区 `.ob-panel-toolbar` 左上（只改本分区，不表示编辑全部 Tab），在当前页打开 Drawer，见 [form-carrier](../form-carrier.md)
- 分组判断见 [detail-page](../components/detail-page.md)
- 字段顺序见上文「字段摆放顺序」
