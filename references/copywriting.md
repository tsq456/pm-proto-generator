# 界面文案规范

> 提炼自 [Ant Design · 文案](https://ant.design/docs/spec/copywriting-cn)。写界面文案与评审原型时优先遵守本文件；实现细节（ProtoMock、localStorage、http 静态服务）**不得**出现在用户可见文案中。

## 总原则

| id | 原则 | 要求 |
| --- | --- | --- |
| P1 | 用户视角 | 以用户能做什么 / 关心什么为立足点，少写「我们为你提供了…」 |
| P2 | 精简 | 省略已知事实与实现细节；一句能说清不写两句 |
| P3 | 熟悉语言 | 用业务方听得懂的词，避免生僻、暧昧、过度文雅 |
| P4 | 表述一致 | 同事物用词统一；同区块介词/语序一致；按钮文案与目标页标题一致 |
| P5 | 重要信息前置 | 关键结论放段首或单独成行，不埋在段落中 |
| P6 | 完整直接 | 引导操作时说明目的/收益；异常说明「发生了什么 + 下一步」 |
| P7 | 用词精准 | 无错别字；行业术语准确；时间表述明确到日/月等 |
| P8 | 语气友好 | 用「你」而非「您」；不命令指责；避免「绝不」等极端词 |
| P9 | 标点克制 | 标题/按钮/单行提示可省略句号；慎用感叹号；数字用阿拉伯数字 |

## 原型包硬约束（MUST）

用户可见文案**禁止**出现：

| 禁止模式 | 示例 | 改为 |
| --- | --- | --- |
| 暴露 Mock / 原型机制 | 「此操作仅影响原型 Mock 数据」 | 「确定删除「名称」？」 |
| 暴露技术栈 / 本地存储 | 「localStorage」「ProtoMock」 | 不写；或业务表述「删除后不可恢复」 |
| 暴露打开方式 | 「请用 http 静态服务打开」 | 「数据加载失败，请刷新后重试」 |
| 开发向口吻 | 「演示数据」「假数据」「测试数据」作主文案 | 「暂无数据」 |
| 原型专用控件 | 页头「重置数据」「重置演示数据」 | 不放进业务页 |
| 英文堆砌无必要 | 无语境的 `Mock`、`TODO`、`WIP` | 中文业务表达 |

允许（非用户主路径）：

- Spec / changelog / 代码注释中说明 ProtoMock
- 旁路「原型说明」Drawer 中的演示覆盖标注

禁止把原型工具做成业务页控件（页头、筛选、表格、弹窗）。包括「重置数据」及任何调用 `ProtoMock.reset` 的按钮。清数据只留在工程侧（控制台 / 脚本），不进产品界面。旁路 FAB「原型说明 / 更新记录 / 导航」与可选「评审工具」条不属于业务页控件。

## 常见句式对照

| 场景 | 推荐 | 避免 |
| --- | --- | --- |
| 删除确认 | 确定删除「{名称}」？ | 确定删除？此操作仅影响原型 Mock 数据。 |
| 空列表 | 暂无数据 | 暂无数据，请新增或重置演示数据 |
| 加载失败 | 数据加载失败，请刷新后重试 | Mock 数据加载失败，请用 http 静态服务打开本页 |
| 成功反馈 | 已删除 / 已保存 | 删除 Mock 成功！ |
| 校验失败 | 请输入园区名称 | 不能为空！！！ |
| 输入占位 | 请输入 | 如：李四 / m² / 元/月（单位用前缀后缀） |
| 范围筛选占位 | 请输入 | 单位放在输入框内作后缀，不另起一行 |
| 表格单位 | 表头「参考租金（元/月）」，单元格 `800` | 每行都写 `800 元/月`（单位随行变化时除外） |
| 选择占位 | 请选择 | 用第一项业务枚举冒充空态 |

## 语言细则（摘录）

### 立足点

- 写「你可以… / 将…」优于「我们为你…」
- 用户反馈/申诉场景可用「我们将会…」

### 精简与熟悉

- 不重复界面已展示的信息
- 少用间接说法与生僻词

### 一致

- 同一对象全程同一名称（如「园区」不混用「园区项目」除非确有区分）
- 操作名 = 落地页标题（如按钮「编辑」→ 弹窗标题「编辑园区」）

### 完整与异常

- 引导设置时说明收益
- 异常用「无法完成 / 未能…」优于冷冰冰「失败」；并给出下一步

### 用词表（节选）

| 使用 | 不使用 |
| --- | --- |
| 其他 | 其它 |
| 登录 | 登陆 |
| 此 | 该（指当前事物时「此」更明确） |
| 抱歉 | 对不起（系统责任时可用「抱歉」；用户责任时勿用） |

### 语气

- 用「你」，少用「您」
- 同一句不要混用「你」「我」导致指代混乱
- 少用「不能」「不要」「请勿」命令口吻；改为引导正确做法
- 避免「绝不」「一定」等极端表述

### 标点与数字

- 统计与数量用阿拉伯数字
- 标签、标题、按钮、单行提示可省略句末句号
- 多句正文保留标点
- 感叹号仅用于问候/祝贺等强情感场景
- 日期连接用半角 `-`（如 2012-11-12）
- 省略号用 `…`

## AI 自检清单

写完或改界面文案后自问：

1. 用户是否看得懂、无需知道这是原型？
2. 是否出现 Mock / ProtoMock / localStorage / 静态服务等词？
3. 是否与同页其他文案用词、语序一致？
4. 确认框是否只陈述后果，不夹实现说明？
5. 空态 / 错误是否给出可执行下一步（且仍是产品口吻）？
6. 无特殊需求时，输入框是否为「请输入」、选择器空态是否为「请选择」？单位是否在前缀/后缀而不是 placeholder？
7. 表格里同一列单位是否只在表头（全角括号）？单元格是否只剩数值？单位会变的列是否写在单元格里？
