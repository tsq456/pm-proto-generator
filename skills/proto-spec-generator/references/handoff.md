# 逐页 Spec → 原型实现交接

## 分工

| 产物/操作 | proto-spec-generator | pm-proto-generator |
| --- | --- | --- |
| 上游快照、接收记录、业务与技术映射 | 接收并维护 | 读取依据，不改业务原稿 |
| sitemap 与逐页说明 | 从上游派生 | 消费并回填实际覆盖 |
| 固定演示数据 | 记录具名对象、关联、场景与映射 | 落地 JSON/脚本，保证跨页一致 |
| kits、HTML、旁路 Runtime | 不生成 | 缺失才补；实现就绪批次 |
| 包根 PRD 汇总 | 提供页面内容 | mountPrdHub 聚合，不再写第二套业务要求 |
| 验收与反馈 | 保留上游验收、列缺口 | 检查实际结果并报告偏差 |

## 交接检查

- 原稿快照存在且未改写；接收记录能追溯版本、章节和确认依据。
- 本批每页文件名、frontmatter、sitemap 和本地映射一致。
- 浮层/Tab 的宿主、共享规则、入口与返回明确；占位替换有依据。
- 每页分开记录产品要求、原型覆盖、真正未决事项。
- 同一对象的技术键和固定场景在各页一致；没有补造影响业务结果的数据。
- 就绪页面及其必要依赖已核对；受阻页面不混入实施清单。
- Spec 阶段检查通过，不以缺 HTML 为错误，不运行全包初始化。

## 主技能接收后的执行顺序

交接完成后，主技能按 [逐页实现选型](../../../references/page-implementation.md)确定页型与宿主、layout、区域组件和复用/新增方案，再编写 HTML。子技能提供业务职责与约束，不替主技能承诺未经检查的组件能力。

主技能在包内 `docs/implementation-map.md` 简记本批选择、实际复用位置、缺口处理和验收点。该记录不作为独立业务依据，不增加用户审批，也不要求只生成 Spec 的任务创建。

## 交接摘要

提供：包根、接收批次、来源版本、本批就绪 page-id、依赖页面、阻塞项及记录链接。主技能只实现就绪部分；用户原请求已包含原型开发时直接继续，不新增一次“交接批准”。

主技能完成后：按上游场景验证，回填覆盖与偏差；仅导航变化时更新壳层与跨页入口，保持包根 PRD 汇总可用；追加包内 changelog。技术映射变化要同步接收记录，不将 HTML 现状倒写为产品要求。
