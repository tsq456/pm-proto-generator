# 新版接收与历史兼容

## 新版输入

先确定完整替换或增量补充，保存新批次快照；旧快照不覆盖。接收记录追加变化与依据；页面/字段/对象映射保持稳定。相同来源和内容重复接收时复用既有记录，不制造新版本或重复文件。

- 完整替换版中未提及的旧页面也不自动删除；明确删除或废弃才实施清理。
- 新版改变业务规则、数据含义或页面职责时，更新受影响逐页说明、依赖与验收；未受影响页保留。
- 先更新文档中的就绪判断，再交实现；派生转换不另求产品确认。
- 上游“需检查”影响本批时暂停受影响部分，保留既有可用原型，不把未确认新版覆盖为已定规则。
- 用户直接提出新的业务能力时反馈上游需要更新的 Spec；样式调整、错字和修复偏离已确认 Spec 的实现不要求新版业务文件。

## 已有包

旧 `docs/spec-review.md`、历史 Spec 和确认引用可复用，保持原位，不为补接收记录重复确认。旧版四分册/嵌套 Spec 继续可读；仅本轮新增页使用扁平文件。历史无来源时记“来源待补”，不能推定现有 HTML 正确；可整理可观察现状，但不据此改变已确认业务规则或宣称实现就绪。

业务名称变化不自动改 page-id。跨包同名页面不共享实体命名空间；同包同一对象跨页使用相同数据标识。

## 数据与覆盖

接收新版数据要求不等于授权重置演示数据。实现时核对已有 store 与新增字段的兼容；不能只改种子文件就宣称旧数据已更新。

当前 ProtoMock 已知的删除种子记录再出现、旧记录缺字段问题留待独立修复，本轮不修改运行库、不承诺已解决。发现影响本批演示时如实标为偏差并报告，不自动清空用户演示数据。
